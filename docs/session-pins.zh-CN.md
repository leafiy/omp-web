# 会话置顶与跨设备同步

## 当前源码行为

- 置顶会话独立显示在侧栏顶部，不在项目分组中重复显示。新置顶的会话排在最前，取消后回到项目分组；置顶按钮仍仅在鼠标经过会话行时显示。
- `lib/session-pin-state.ts` 将网页置顶列表保存到服务用户的 `~/.config/omp-web/session-pin-state.json`。原子替换、文件权限 `0600`；可用绝对路径 `OMP_WEB_PIN_STATE_FILE` 覆盖。它不修改任何引擎的原生会话、配置或凭据。
- 同一 omp-web 服务的所有已登录设备共享这份列表，服务重启后保留。不同服务器实例之间不会自动复制文件。
- ID 使用完整的网页会话 ID，包括 Pi、Claude Code、Codex 前缀，不跨引擎合并。不解析或启动引擎，尚未写入原生历史的新会话也能置顶。
- `GET /api/sessions/pins` 返回 `{ pinState: { revision, pinnedSessionIds } }`；`POST` 接受 `{ sessionId, pinned: boolean }`，只修改指定会话。重复设为已置顶不会变成取消或重新排序，旧设备不会用整份列表覆盖其他设备的修改。同一会话的冲突操作以服务端处理顺序为准。
- 这些 API 复用 `proxy.ts` 的登录、Host 和 Origin 检查；响应禁止缓存。
- 首次加载 `/api/sessions` 和侧栏既有的 `/api/agent/running` 轮询都携带置顶快照。可见页面每 2.5 秒同步；恢复可见、网络恢复时立即同步。浏览器拒绝版本落后的响应，避免迟到的轮询撤销刚保存的操作。
- `hooks/useSessionPins.ts` 仅在服务端确认保存后更新列表，保存期间禁用对应按钮，失败时显示提示。删除已置顶会话后也请求清除置顶；列表中不存在的 ID 不渲染。不能因某次会话列表暂缺 ID 就全量清理置顶，以免丢失尚未落盘或暂不可见的会话。

## 旧浏览器数据

不再读取或写入旧的 `omp-web:pinned-sessions`，新版页面会移除该本地键，不自动上传，以免旧设备恢复另一设备已取消的置顶。升级后原有本地置顶需要重新设置一次，之后由服务端统一保存。旧页面需要刷新到新版。

## 验证范围

新增 `lib/session-pin-state.test.mjs`：四引擎 ID、跨设备操作、重启恢复、幂等与排序、快照隔离、持久化失败、损坏数据、API 参数校验及文件权限。`components/SessionSidebar.test.mjs` 增加服务端快照接入、移除本地持久化及悬停按钮的源码断言。

这些用例只使用临时文件和进程内 API 调用，不启动原生引擎或请求模型。需获得本任务单独授权后运行；源码修改不代表测试已通过、已构建或已部署。
