# 排队消息取回编辑

CC 的未处理消息旁增加“取回编辑”。网页按原生 UUID 请求 `cancel_async_message`，只有明确的 `cancelled: true` 才报告取回成功；随后把原文放回草稿，与已有草稿合并，而不是覆盖。修改后由用户再次选择发送方式，不自动补发，不保证重新排入原来的位置。

- 不停止当前任务，不修改已经送入模型的消息，也不只改网页文字而让旧内容继续执行。
- 已开始处理或未确认取消时明确提示，保留原文副本；用户应先检查队列和历史，避免重复发送。
- 取回期间防止重复点击；切换会话后确认成功的文本保存在原会话的内存草稿里，不插入另一会话。
- 当前固定 SDK 0.3.318 的取消请求运行时接口集中在 `lib/claude-steering.ts`，不接受客户端自定义控制命令。只允许取回本网页跟踪的未开始 UUID，不操作其他来源的消息。
- OMP 保留已有的“移回输入框”批量取回能力，恢复明确移除的文字后再读取状态，避免后续网络失败丢失已取回文字。其原生接口按文字移除，未伪造逐条稳定 ID。Pi 暂无可靠取回接口，Codex 尚无网页排队入口，不显示假的逐条编辑按钮。

原生验证使用真实 CC 和真实网页适配器连接本地假模型服务；网络仅 loopback、空 HOME/config 和假 Key。两种优先级的待处理文字均成功撤回，原文字未进入后续合成模型请求。另用模拟 SDK 验证已开始、取消失败、不停止、不自动重发等边界。没有调用真实模型或读取真实登录文件。

队列与草稿都是运行时内存状态，不承诺跨网页刷新、服务重启或 CLI 退出持久化。
