# Claude Code 上下文容量

## 原因与修复

旧网页没有把 CC 的上下文容量接入状态接口，同时在缺失时写死回退到 `128000`，因此显示 128K。这个值不能说明原生 CC 真正受限于 128K。

现在通过当前 CC Query 的 `getContextUsage({ detail: "summary" })` 读取上下文摘要：

- 使用原生 `maxTokens` 作为当前有效窗口；`rawMaxTokens` 是另一字段，不能在有效窗口缺失时擅自替代。若 CC 调整有效预算，显示会跟随原生值。
- 使用原生 `totalTokens` 和 `percentage`，不把累计计费 Token 或上一条回复的输入数猜成当前上下文，也不自行重算/扩大原生百分比。
- 只返回容量、Token 数和百分比；不向网页传出摘要中的记忆文件路径、工具列表或其他私有内容。
- 缺失、无效、不支持或超时时显示“上下文未知”，不回退到 128K、200K 或 1M。
- 有效原生窗口优先于模型目录，即使它比目录标称值小。前端不再通过模型名包含关系误匹配窗口。
- 手机顶栏优先完整显示容量，避免被右侧按钮遮住；点击会话信息可查看百分比等详细统计。

## 2026-11-08：顶栏上下文时有时无

原实现在 Agent 运行中或摘要读取超过 1.5 秒时返回 `null`；浏览器回合结束只读一次状态，读取若超时便一直显示“上下文未知”，直到下一轮。修复：

- 回合开始/结束仍使缓存失效并重新读取，但运行中、读取较慢或失败时返回**最近一次原生摘要**，不再清空为未知。只有切换模型（窗口可能改变）和会话关闭会清除它。
- 每轮结束后后台读取一次摘要；数值到达时通过 SSE `context_usage` 推送给浏览器，不依赖那一次状态请求的时机。
- 这仍然是原生 `getContextUsage({ detail: "summary" })` 的结果，不用累计计费 Token 或回复输入数推算。

其他引擎同期修复（同一顶栏）：

- Pi RPC 的 `get_state` 没有上下文字段，原先只能显示模型目录窗口（`? / 窗口`）。现在 `get_state` 额外读取 Pi 原生 `get_session_stats.contextUsage`；`get_session_stats` 也不再被缺失字段覆盖。压缩后原生未知仍显示未知；读取失败视为未知，不保留可能属于旧模型窗口的值。
- Codex 原来固定返回 `null`。现在采用 app-server `thread/tokenUsage/updated` 中本线程的 `tokenUsage.last.totalTokens`（Codex 自身的“上下文内 Token”）和 `modelContextWindow`，百分比为二者之比；`total` 是累计计费，绝不当作当前上下文。切换模型后等待新窗口上报；子线程更新被忽略。
- OMP/Pi/CC/Codex 进程空闲 10 分钟退出后再打开历史，原先只能显示目录窗口或未知。服务端现在按网页会话 ID 保留最近一次**原生报告**的值（最多 500 个；2026-11-10 起跨重启持久化，见下节），状态接口在无活动进程时作为 `lastContextUsage` 返回；不从历史消息推算。原生明确报告未知时会删除这条记录。

## 2026-11-10：重启服务后历史会话显示“上下文未知”

原因：上面的“最近一次原生报告”只保存在服务进程内存中。部署或更新会重启服务，之后打开的历史会话（进程已退出）都没有可返回的值，只能显示“上下文未知”，直到该会话再运行一轮。本次排查时服务刚在 20:47 重启过。

修复：服务启动时（`instrumentation.ts`）启用持久化，把最近一次原生报告写入 `$XDG_STATE_HOME/omp-web/context-usage.json`（默认 `~/.local/state/omp-web/`，目录 0700、文件 0600，原子替换）。

- 仍然只保存引擎报告过的 `contextWindow / tokens / percent`，不保存会话内容或路径，也不根据历史消息推算。
- 只有数值变化才写盘（1 秒合并一次），状态轮询重复同一值不写。原生明确报告未知、删除会话时同步移除。上限仍为 500 个会话，读取时重新校验每条记录；文件缺失或损坏时从空开始，不改写它。
- 本进程启动后收到的报告优先于文件中的旧值。测试和其他工具不调用启用函数，只用内存，不会写入用户目录。
- 局限：本修复上线前从未在新进程里报告过的历史会话仍显示未知，运行一轮后才有值。在终端里继续过的会话会显示网页最后一次看到的值，直到在网页中再次运行。

## 请求边界

只调用 `detail: "summary"`，不使用默认的 `full`，不调用额外的分类 Token 计数 API，不发送模型提示。

读取缓存限定在当前原生会话内，短缓存十秒；并发请求合并。开始/结束回合、模型切换、原生初始化和关闭时使旧摘要失效（需重新读取）；其中只有模型切换和关闭会清除“最近一次摘要”。Agent 正忙或正在切换模型时不另发摘要请求，返回最近一次摘要。网页等待超过 1.5 秒则返回最近一次摘要（没有则未知），不杀死聊天；底层未完成的读取仍保持单个，防止请求堆积，完成后推送。迟到结果不能跨模型/回合生效。

切换模型时前端立即清除旧容量，并重新读取状态；恢复历史没有可用原生摘要（也没有本次服务运行期间记录的原生值）时仍显示未知，不根据旧消息猜容量。

## 本次验证

本机和 `192.168.52.3` 的服务用户 HOME 下，各进行了一次非持久化 CC 摘要检查；两边均返回 `maxTokens = rawMaxTokens = 1000000`。这是各自该工作目录的原生默认配置结果，不代表所有项目、模型或账号统一有 1M。没有传入模型覆盖，没有读取/复制登录文件，没有发送提示或调用额外 Token 计数 API。

模拟回归覆盖 1M、200K、原生真实 128K、未知容量、原生百分比、并发合并、超时、模型切换和迟到响应。浏览器覆盖未知/1M/200K、模型切换、历史恢复和手机布局。

入口：`lib/context-usage.test.mjs`、`lib/claude-code.test.mjs`；实现：`lib/claude-context-cache.ts`、`lib/context-usage.ts`、`lib/claude-code-session.ts` 和聊天统计界面。
