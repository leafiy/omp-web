# 长对话：分页与显示缓存

缓存只用于网页显示，不截断或替换原生 Agent 的上下文，也不改写历史文件。

## 加载方式

- 初次读取最近 60 条消息；上翻后可点击“加载更早消息”。原生 entry ID 与消息保持一一对应，分支导航和 Fork 继续使用原生 ID。
- 分支树只传导航元数据和短预览，不重复携带完整正文、思考或图片。CC/Pi/Codex 不需要 OMP 分支树时不传该树。
- 大于约 24K 字符的单条消息先传占位信息，用户点击“加载完整内容”后再读取；工具输出、图片、长文本同样适用。展开的完整内容只保存在当前视图，不塞进最近会话缓存。
- 统计携带未加载前缀的汇总，因此显示的是当前分支完整历史统计，不把一页消息数误报为总数。上下文容量仍读取原生接口，绝不从分页内容推算。

## 两层内存缓存

- 浏览器：当前标签页内存，最多 8 个请求页/快照和约 20 MiB 估算预算；不写 localStorage 或 IndexedDB。切换回来先显示已有快照，同时重新校验；相同的并发请求合并。
- 服务端：只读文件解析快照，最多 16 个文件、约 64 MiB 估算预算。每次用设备、inode、大小、mtime 和 ctime 校验文件身份；追加、替换、改名或删除后不沿用旧版本。
- HTTP：使用 ETag 条件请求，未改变时返回 304、无正文。`private, no-store` 禁止共享/磁盘 HTTP 缓存，条件请求由页面自己的内存缓存管理。认证和 Origin 检查在 304 判断前执行。

收到实时消息、成功改名/删除时使对应浏览器快照失效；401/403 清空缓存。页面不缓存运行状态、审批或原生队列。迟到的历史响应不能覆盖新消息、模型选择或其他会话。加载更早消息带文件版本和分支游标；版本变化时重新读取，不混接不同快照。

## 验证与限制

使用合成的 3000 条消息基准：原始接口每次返回约 9.77 MB（gzip 5.16 MB）；分页后约 234 KB（gzip 113 KB），未改变的条件请求无正文。服务端热请求处理从该样本的约 34 ms 降到约 4 ms。

浏览器使用独立合成历史目录，模拟 150 ms 延迟、128 KiB/s 下载。初次打开另一个长会话约 2 秒，切回已有缓存的会话约 0.1 秒；具体值以发布目录的 `history-browser-result.json` 为准，不代表用户真实 VPN 的保证值。验证没有读取用户聊天正文。

首读仍需解析完整文件，特别巨大的历史或高度分叉的导航树仍有开销；缓存采用有界估算而非无限常驻。浏览器刷新会清掉内存缓存，首次打开主要依赖分页和按需读取减量。
