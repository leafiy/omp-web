# 非阻塞的页面确认

网页不使用浏览器原生 `alert()`、`prompt()` 或 `confirm()`。本次源码检查未发现原生 alert/prompt，替换的是终止终端、四工具更新和旧 OMP 更新入口的三处 `window.confirm()`。

这些操作使用 `components/InlineConfirmation.tsx`：

- 确认内容出现在操作所在区域，没有新的全屏蒙层，不使用原生对话框，也不阻塞 JavaScript、流式消息或状态轮询。
- 默认聚焦取消；Esc 仅在确认区域内取消，不拦截页面其他区域的键盘操作，不设置全局焦点陷阱。
- 每次确认只能回答一次，防止重复点击。取消或关闭所属面板不会执行操作。
- 真正提交前仍检查可用状态。终止终端固定到显示确认时的终端 ID；软件更新固定到显示的工具，不取消后端确认、认证或更新锁。
- 设置面板与全局快捷键尊重已处理的键盘事件，避免取消确认时意外停止聊天。

已有的页面错误提示（如 `role="alert"`）和 Agent 的异步输入/审批界面不是浏览器阻塞弹窗，继续保留。模型的 `prompt`、工具的 `confirm` 接口也不应被误改为 UI 通知。

验证入口（需按仓库规则单独获得授权）：

```sh
node --test components/InlineConfirmation.test.mjs lib/browser-dialogs.test.mjs
```

还需用浏览器模拟检查：取消不提交、明确确认只提交一次、等待确认时流式输出继续、Esc 不终止 Agent、切换目标/关闭面板不误提交、终端收起时仍可看到确认，以及手机布局。模拟更新/终止接口，不执行真实 CLI 更新或终止真实终端。
