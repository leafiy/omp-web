# 会话未读与跨设备已读

## 原因

旧版 `SessionSidebar` 用浏览器 `localStorage` 保存未读 ID，仅在本设备打开会话时清除。设备之间不共享清除动作；休眠设备还会把自己保留的旧运行快照与恢复后的空闲状态比较，再次产生未读标记。此逻辑由四种引擎共用，不是 Claude Code 原生历史中的未读属性。

## 当前源码行为

- `lib/session-read-state.ts` 统一保存网页会话的完成记录。`rpc-manager.notifyRunningChange()` 在没有 SSE 订阅者时也记录运行到空闲的变化；使用包含队列、后台任务和命名工作的会话包装层状态，不把单个 `agent_end` 当作结束。
- `FollowUpSession` 在释放手动请求的 busy 计数后也发布状态，避免原生结束通知先于包装层 `finally` 时遗漏最终空闲状态。
- 默认持久化到 `~/.config/omp-web/session-read-state.json`，原子替换、文件权限 `0600`。可用绝对路径 `OMP_WEB_READ_STATE_FILE` 隔离测试数据。它不修改任何引擎的原生历史或认证数据。
- `/api/agent/running` 的现有轮询携带 `{ revision, unread }`。可见页面每 2.5 秒同步；恢复可见时立即拉取。运行记录由当前服务进程观察，服务重启不把中断的任务凭空当成完成。
- `POST /api/sessions/read` 接受会话 ID 到完成版本的映射，只清除匹配版本。迟到的另一台设备的已读请求不能清除下一轮结果；浏览器也拒绝较旧版本的响应。
- 选中的会话仅在页面可见时自动确认已读。项目标题旁的双勾按钮批量确认该项目所有会话，包括折叠或未展开显示的会话。不取消正在运行的任务，也不隐藏待确认对话框。
- 保存失败不乐观清除标记；页面展示同步失败提示。选中会话随下一次轮询重试，批量操作可以再次点击。

## 旧数据处理

旧的 `omp-web:unread-session-ids` 仅有设备本地布尔标记，无法知道是否已在其他设备读过，也没有对应轮次。新版移除它而不上传，避免将历史误报重新导入服务端。因此首次升级会清除旧版残留提醒，之后由新完成记录驱动。打开过的旧网页需刷新到新版。

## 验证范围

新增 `lib/session-read-state.test.mjs` 覆盖四引擎 ID、跨设备确认、持久化恢复、过期回执、项目批量确认、重复轮询和文件权限；`lib/follow-up-session.test.mjs` 增加原生结束早于包装层释放 busy 的用例。需获得任务专属运行授权后执行；源码修改不代表测试通过或已部署。
